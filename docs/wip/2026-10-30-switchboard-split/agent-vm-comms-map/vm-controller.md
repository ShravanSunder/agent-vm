## Representative paths and returns

### Start a configured zone

source: `controller.start` loads config and requires an already prepared matching Gateway image; absent/stale cache throws before controller startup. The default dependency selects Gondolin and injects neutral capabilities. (`packages/agent-vm/src/cli/commands/controller-command-operation.ts:120-138,315-337`; `packages/agent-vm/src/cli/agent-vm-cli-support.ts:145-154`)

source: Runtime acquires the deployment lock, reconciles old recorded VM trees, and aborts admission as owner-unsafe on unproven cleanup; only then does it assemble the live runtime. Controller HTTP binds before selected Gateway start, so `/health` may return `503` during startup. Selected-zone failures retain failed zone snapshots; after `startSelectedZones()` returns the global runtime becomes ready, so global readiness is not proof that every zone is healthy. (`packages/agent-vm/src/controller/controller-runtime.ts:1982-2029,1740-1747,1808-1822`; `packages/agent-vm/src/controller/http/controller-http-routes.ts:53-62`; `packages/agent-vm/src/controller/zone-runtimes/zone-runtime-registry.ts:149-162`)

source: Gateway startup creates/starts the exact VM candidate, admits its cohort, enables ingress with WebSockets and response buffering disabled, registers controller control handlers, connects to that ingress, reaches aggregate readiness, writes runtime record and control material, then returns the handle. CLI writes controller port, selected zone ingress, and VM id; process-root CLI awaits shutdown signals. (`packages/agent-vm/src/gateway/gateway-zone-orchestrator.ts:1974-2037,2138-2153,2224-2232,2465-2523`; `packages/agent-vm/src/cli/commands/controller-command-operation.ts:198-206,278-305`)

### A declared agent requests a Tool VM

source: For a declared agent with an assigned/fallback profile, trusted caller context selects zone/agent workspace and optional Git root via controller config. Requests do not author the host roots. Lease RPC awaits lease creation and privately serializes the result back to the Gateway. (`packages/agent-vm/src/controller/leases/managed-framework-tool-vm-lease-create-options.ts:60-117`; `packages/agent-vm/src/controller/control-session/gateway-control-lease-rpc.ts:487-518,840-864`)

source: Creation allocates a TCP slot, begins retained provisioning and provisional Gateway-child membership, prepares persistent workspace state, creates the unstarted Tool VM, attaches VM identity, starts it, captures and writes exact runtime evidence, awaits any predecessor admission barrier, prepares the started VM, enables SSH, checks server identity and commits current membership/lease. (`packages/agent-vm/src/controller/leases/lease-manager.ts:950-1119`)

source: Tool creation requires prepared image selection, resolves only allowed Tool-VM mediated secrets, uses COW rootfs and an owned filtered workspace view; bootstrap resets inherited SSH host identity, configures Git safe directory, and installs mediated placeholders. Returned SSH details let Gateway runtime operate directly against the Tool VM. (`packages/agent-vm/src/tool-vm/tool-vm-lifecycle.ts:380-406,426-480`; `packages/agent-vm/src/controller/control-session/gateway-control-lease-rpc.ts:292-425`; `packages/gateway-runtime/src/sandbox/strict-tool-vm-ssh-client.ts:337-385`)

### Dead/stale Tool VM, expiry, and release

source: Renewal classifies expired leases separately from dead VMs; expiry requires no active uses. The reaper releases idle-expired leases sequentially, and ordinary release is blocked by active use unless forced. (`packages/agent-vm/src/controller/leases/tool-vm-lease-lifecycle.ts:32-61`; `packages/agent-vm/src/controller/leases/idle-reaper.ts:17-48`)

source: Reacquire checks the old lease's retained authority, current caller principal/Gateway and compatibility; missing authority returns typed `lease_authority_absent`, mismatch returns `ownership_denied`. It invokes controller `reacquireLease`, then serializes the replacement; it does not treat stale lease id as authority for a fresh ordinary create. (`packages/agent-vm/src/controller/control-session/gateway-control-lease-rpc.ts:588-675`)

source: Retirement first fences access with exact recorded process termination; resource cleanup closes the VM, verifies runner detachment, closes SSH and verifies endpoint absence, cleans receiver staging, deletes runtime record, records membership destroyed, and releases slot only on completed destruction. Errors preserve retained context and quarantine the slot. (`packages/agent-vm/src/controller/leases/lease-manager.ts:464-505,655-747,763-796`)

### Gateway failure, controller crash, and shutdown

source: Health monitor wiring probes live service health, can ensure current control-session dialing, and calls Gateway VM recovery with current identity source keys. Recovery action classifies running/degraded as restart, stopped/cold-start-eligible failed as cold start, owner-unsafe as operator-required, and starting/restarting/stopping as observe-only. (`packages/agent-vm/src/controller/controller-runtime.ts:1850-1911`; `packages/agent-vm/src/controller/health/gateway-recovery-actions.ts:38-89`)

source: Restart/offline reconciliation does not adopt old VMs: under the deployment lock it rejects legacy authority in Gateway state, contains credentialed runtimes, cleans Tool records, and only then cleans their Gateway record. Any unsafe credentialed result, Tool warning/quarantine or Gateway cleanup warning aborts. Offline `--force` skips only controller reachability probing, after lock acquisition. (`packages/agent-vm/src/operations/controller-offline-cleanup.ts:86-162,179-192`; `packages/agent-vm/src/controller/controller-runtime.ts:1982-2029`)

source: Normal close marks stopping, aborts controller work, clears reaper, awaits health-monitor stop, drains OAuth admission/listener, stops all zones, closes HTTP, flushes evidence/telemetry, and aggregates errors. The outer runtime releases ownership lock last unless error ancestry contains owner-unsafe. (`packages/agent-vm/src/controller/controller-runtime.ts:1913-1972,2049-2083`)

## Storage and image prerequisites

source: `storageRootDir` determines shared cache/deployment cache/generated roots. Gateway durable state and per-agent zone files are backed up; image artifacts, generated selections, controller runtime logs/lock and per-agent runtime Git databases are separate. Controller authority has its own host-only durable root excluded from normal zone backups. (`docs/architecture/storage-model.md:19-93,95-140,158-193`)

source: The actual backup archive implementation includes only staged `state`, optional `zone-files`, and `manifest.json`, then encrypts and deletes the plaintext tar. It validates that runtime dirs do not overlap backup input roots. This establishes the archive selection, not a claim of live consistent VM snapshots. (`packages/agent-vm/src/backup/backup-create-operation.ts:21-77,131-156`)

source: Runtime `prepareImage` with a configured selection path only reads a prepared image and fails if invalid; it falls back to provider build only when no selection path was supplied. Managed Tool creation supplies a selection record. CLI Gateway startup separately recomputes expected fingerprint using current runtime boot projection. Thus image preparation is a prerequisite crossing build/runtime ownership, not a background boot service in these managed paths. (`packages/agent-vm/src/composition/gondolin-managed-vm-provider.ts:32-63`; `packages/agent-vm/src/tool-vm/tool-vm-lifecycle.ts:396-406`; `packages/agent-vm/src/cli/commands/controller-command-operation.ts:68-138`)
