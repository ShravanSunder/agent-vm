source: Host health/recovery observes framework readiness, control connectivity and current runtime identities; the host lifecycle restarts or cold-starts the Gateway VM according to current state and policy. The guest Node service owns its own orderly resource retirement, not the Hermes process. (`packages/agent-vm/src/controller/controller-runtime.ts:1850-1911`; `packages/agent-vm/src/controller/health/gateway-recovery-actions.ts:38-89`; `packages/gateway-runtime/src/production/gateway-runtime-production-lifecycle.ts:127-193`)

## Health, recovery and return/error paths

source: Startup admission joins current VM liveness, control acceptance, framework-native readiness and Tool Portal readiness/attachment; individual readiness facts are observed through explicit suppliers before ingress publication. Framework metadata names `/health` on guest port 8642. (`packages/agent-vm/src/gateway/gateway-zone-orchestrator.ts:1996-2020`; `packages/hermes-gateway/src/hermes-lifecycle.ts:289-309`)

source: The startup observation loop runs the framework guest curl, marks current framework evidence only on success, detects changed host PID, feeds the aggregate snapshot to the admission controller, and returns only on `admitted`; waiting retries are bounded and unexpected contained states fail startup. (`packages/agent-vm/src/gateway/gateway-zone-orchestrator.ts:2384-2445`)

source: Host framework health probe is `vm.exec`-style command execution of guest-loopback curl, yielding observed HTTP status; it is distinct from signed control readiness and from host controller `/health`. HTTP success is `2xx`, command success is exit zero. (`packages/agent-vm/src/gateway/gateway-health-check.ts:14-53`; `packages/agent-vm/src/controller/controller-runtime.ts:1861-1879`)

source: Runtime publishes readiness to protected local evidence and over the control channel; attachment changes update those snapshots, and a heartbeat publisher is owned by the Node service. Startup failure runs ordered partial rollback and writes fatal evidence; multiple startup/rollback failures become an AggregateError. (`packages/gateway-runtime/src/production/gateway-runtime-production-service.ts:649-658,687-765,789-842`)

source: Control disconnection clears the guest accepted session, closes application work, resolves waiters unavailable and rejects pending command results; the host owns bounded manual redial instead of Socket.IO auto-reconnect (`reconnection: false`). Current configured host bounds are 60 seconds/16 attempts, with heartbeat/stability accounting. (`packages/gateway-runtime/src/control-endpoint/gateway-control-session-service.ts:307-319`; `packages/agent-vm/src/controller/control-session/gateway-disposable-control-session-client.ts:57-60,272-280`; `packages/agent-vm/src/controller/control-session/gateway-control-session.ts:454-549`)

source: Health monitor is conditional on controller health config; its dead-control callback asks the current zone runtime to resume dialing. Recovery policy maps running/degraded to VM restart, stopped/cold-start-eligible failure to cold start, secret-resolution failure to resolver refresh, and owner-unsafe/ambiguous states to operator-required. This is host-level VM recovery, not a per-child guest restart manager. (`packages/agent-vm/src/controller/controller-runtime.ts:1850-1911`; `packages/agent-vm/src/controller/health/gateway-recovery-actions.ts:38-89`)

source: The recovery runner rejects work while controller is stopping, resolves the current zone runtime, rejects stale/missing recovery source identity for a running VM, classifies action, and calls runtime credential refresh, cold start or restart under a deadline. (`packages/agent-vm/src/controller/health/gateway-vm-recovery-runner.ts:143-235,271,330`)

source: Gateway destruction first disposes the control session and withdraws ingress routes/listener, then invokes exact VM ownership destruction; only afterward does it delete runtime records and control material. The transaction records completed cleanup stages, retries incomplete stages, reports `destroyed-cleanup-incomplete` separately from `destroyed-clean`, and retains an exact-destruction failure. (`packages/agent-vm/src/gateway/gateway-zone-orchestrator.ts:1778-1844`; `packages/agent-vm/src/gateway/gateway-zone-destruction-transaction.ts:55-124`)

source: Node retirement stops heartbeat production, retires/drains UDS, retires lease-binding runtime, unsubscribes attachment publication, flushes evidence/control/heartbeats, closes control endpoint, closes MCP provider runtime and retires artifact epoch, recording stage failures rather than abandoning later cleanup. Telemetry then shuts down. (`packages/gateway-runtime/src/production/gateway-runtime-production-lifecycle.ts:127-193`; `packages/gateway-runtime/src/production/gateway-runtime-production-service.ts:776-784`)

source: Python return/failure cleanup closes inventory/cache state, plugin configuration, managed policy/process/environment bindings, adapter client loop and telemetry in nested finally blocks. This cleanup is reached when the upstream framework runner returns or raises; source does not prove graceful receipt when the whole VM is force-terminated.
