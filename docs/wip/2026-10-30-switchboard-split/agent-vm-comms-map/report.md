# How Agent VM communicates — current source map

Agent VM is a host-owned VM system with a long-lived Gateway VM, a Node tool runtime beside Hermes inside that VM, and separately owned Tool VMs and credentialed command VMs. **Tool control is already distributed between the guest Node runtime and the host controller.** The controller owns VM lifecycle, durable approval authority and OAuth credential custody; the guest runtime owns the tool-facing composition and reaches ordinary Tool VMs directly over SSH. Moving one package would not move all of that behavior.

This is a description, not a proposed repository split. Nothing here marks a package as moving or deleted. Effect remains parked.

## 1. One map: the old managed system

```text
Human / channel
       |
       v
Gateway VM                         Host controller
  Hermes framework                 agent-vm
       |                                |
       | private JSON-RPC over UDS       | owns VM creation, leases,
       v                                | durable approvals and credentials
  Gateway Runtime <====================>|
  Node Tool Portal   signed Socket.IO   |
       |             control session    +--> Credentialed command VM
       |             opened by HOST     |    provider exec; host mediation
       |                                |
       +--> Remote MCP provider         +--> OAuth broker + browser UI
       |    HTTP / SSE / child stdio    |    SQLite catalog; Google HTTPS
       |                                |
       +--> Leased Tool VM <------------+
            strict SSH command/file      creates VM and publishes binding
            data from Gateway Runtime
```

Solid relationships above are **seen in the pinned repository source**. The first channel-to-Hermes session loop is an **external-image continuation**, not a locally inspected implementation. No running deployment was observed. The controller-to-provider arrows are in-process capability calls that result in VM/process effects; they are not an existing remote controller service API for another product.

The map separates **control** from **command/file data**: the host initiates the control connection; the guest can request leases and approvals on it; command bytes to a leased Tool VM use SSH. The controller does execute separately configured host and credentialed-managed-VM actions. ## 3. The old system, by responsibility

All items in this section are **today / Source (`M`)**.

### Configuration and CLI: deployment inputs become protected runtime inputs

The CLI parses an operation and invokes its operation owner. `controller start` loads a selected system configuration and checks a prepared matching Gateway image. Other commands validate/build images, inspect or control the running loopback controller, manage backup data, or perform explicit protected administrative work. A CLI invocation is not necessarily a new controller process. Entry: [packages/agent-vm/src/cli/agent-vm-entrypoint.ts:53-76](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/cli/agent-vm-entrypoint.ts#L53); controller command: [packages/agent-vm/src/cli/commands/controller-command-operation.ts:68-138,278-370](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/cli/commands/controller-command-operation.ts#L68).

`system.jsonc` is the root of configuration, **not the only configuration file**. Its schema declares host/controller settings, storage root, image profiles, zones, agents, secrets, egress, Tool VM profiles and pool policy. Each zone references Hermes configuration and optionally a Tool Portal configuration directory. That directory supplies `mcp.config.jsonc` (providers/transports/secrets), `tool-portal.config.jsonc` (agent/profile/backend policy), and optionally `oauth.config.jsonc` (provider/account policy). Shared `config-contracts` parses and compiles the latter; Agent VM's own system schema owns VM deployment configuration. [packages/agent-vm/src/config/system-config.ts:747-792,1704-1712](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/config/system-config.ts#L747); [packages/agent-vm/src/operations/config-validation.ts:203-247,282-340](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/operations/config-validation.ts#L203); [packages/config-contracts/src/index.ts:1-14](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/config-contracts/src/index.ts#L1).

The controller checks declared agents, required approval authority, OAuth policy/catalog compatibility and image inputs before materializing effective protected inputs. ### Controller: live orchestration plus durable authority

The controller holds the deployment ownership lock, selected-zone registry, leases, TCP slot pool, credentialed-runtime manager, approval ledgers, OAuth broker/policy service, health/recovery and loopback Hono HTTP server. Its selected zones may start independently; global HTTP readiness and individual zone health are different facts. The server is started before Gateway admission completes. [packages/agent-vm/src/controller/controller-runtime.ts:559-612,684-722,823-934,1002,1685-1756,1808-1822](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/controller-runtime.ts#L559); [packages/agent-vm/src/controller/zone-runtimes/zone-runtime-registry.ts:149-162](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/zone-runtimes/zone-runtime-registry.ts#L149).

The loopback API handles health/status and explicit zone/admin operations. It is **not the managed tool-call data path**. Managed lease and tool-control requests arrive on the private Gateway control session. The HTTP app is not wrapped in one universal bearer guard: selected operations resolve configured zone admin authority individually. [packages/agent-vm/src/controller/http/controller-http-server.ts:6-24](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/http/controller-http-server.ts#L6); [packages/agent-vm/src/controller/http/controller-http-routes.ts:42-104](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/http/controller-http-routes.ts#L42); [packages/agent-vm/src/controller/controller-runtime-operations.ts:129-185,238-262](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/controller-runtime-operations.ts#L129).

### Gateways: one VM, two sibling processes, host supervision

`gateway-lifecycle` defines neutral requirements and boot inputs. `hermes-gateway` supplies the statically selected Hermes implementation: mounts, resources, mediated secrets, synthetic Tool VM hosts and framework metadata. Neither package is a separately deployed server just because it is a package. Agent VM's orchestrator owns the running VM. [packages/agent-vm/src/gateway/gateway-lifecycle-loader.ts:1-11](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/gateway/gateway-lifecycle-loader.ts#L1); [packages/hermes-gateway/src/hermes-lifecycle.ts:323-396](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/hermes-gateway/src/hermes-lifecycle.ts#L323).

The image boot script starts Node Gateway Runtime and Python Hermes as isolated-environment siblings; it has no child restart loop. Node owns UDS/control endpoints, tool/provider composition, binding/active-use state, artifacts and telemetry. Python installs the managed profile/tool/process hooks, attaches to Node, prepares catalogs and starts upstream Hermes. Durable framework state is mounted at `/home/hermes/.hermes`. The controller supervises service/VM readiness and chooses recovery at the VM level. ### Managed VMs and leases: controller owns meaning; provider performs VM effects

The production composition selects Gondolin once and injects `managed-vm` capabilities for VM construction, prepared images, owned directories and exact process termination. Controller and domain code use those capabilities; the adapter translates them into Gondolin VM, VFS, network/HTTP-hook and SSH operations. It is an in-process SDK boundary, not a network controller-to-Gondolin RPC service. [packages/agent-vm/src/composition/gondolin-managed-vm-provider.ts:23-76](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/composition/gondolin-managed-vm-provider.ts#L23); [packages/gondolin-vm-adapter/src/managed-vm-provider.ts:519-584](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/gondolin-vm-adapter/src/managed-vm-provider.ts#L519).

A Tool VM lease binds the current Gateway generation, authenticated agent/profile revision, controller-selected roots, Tool VM process identity, SSH identity and server pin, TCP slot and timestamps. Reuse requires compatible current authority; active use prevents normal idle retirement. Creation provisions a VM, starts it, persists exact runtime evidence, then opens SSH and publishes current binding. Reacquisition is a distinct fenced operation, not a stale lease ID granting a new lease. [packages/agent-vm/src/controller/leases/lease-manager.ts:73-114,172-249,950-1119](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/leases/lease-manager.ts#L73); [packages/agent-vm/src/controller/control-session/gateway-control-lease-rpc.ts:588-675](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/control-session/gateway-control-lease-rpc.ts#L588).

Retirement fences access, terminates/closes the VM, checks SSH endpoint absence, cleans staging and records, and releases the slot only after destruction completes. An uncertain cleanup preserves context and quarantines the slot. Recovery records are authority for cleanup, not credentials to adopt an old VM. [packages/agent-vm/src/controller/leases/lease-manager.ts:464-505,655-747](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/leases/lease-manager.ts#L464); [packages/agent-vm/src/controller/leases/tool-vm-recovery.ts:254-304](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/leases/tool-vm-recovery.ts#L254).

### Storage, images and distribution: persistence has several meanings

| State | Owner / lifetime | Boundary |
|---|---|---|
| Zone framework state | Framework writes selected mounted state; survives VM replacement | Backed-up zone `state`; includes Hermes home |
| Agent workspace | Controller selects root; agent writes allowed filtered view | Persistent `/workspace`; optional separate `/gitdirs`; disposable COW `/work` is different |
| Controller authority | Controller only | `controller-state/zones/<zone>` contains approval/VM/credentialed-runtime/OAuth authority; not a guest mount and not normal zone backup content |

| Images and generated inputs | Build/materialization owners | Rebuildable cache and selection records; runtime consumes prepared selections |

### Tool control and external effects

Guest Tool Portal resolves caller/profile, capability visibility, policy and the backend to invoke. The host rechecks protected controller actions, account policy and durable approval authority; it owns credentials and current VM authority. Remote MCP provider connection/runtime lives in the guest for managed mode. The backend kinds do not correspond one-to-one to the four product tool kinds. For example a per-user Google tool is a configured CLI into a credentialed Managed runtime, not a generic OAuth-aware upstream MCP connection. See paths below and [full legacy tool map](legacy-tools.md).

Workspace Git is another existing host effect: guest Tool Portal requests the configured operation over control RPC; the controller selects the configured agent workspace and remote/branch, performs sanitized host Git with its host-only credential, and returns the result. It refuses the configured default branch and distinguishes pre-dispatch failure from possible remote mutation. [packages/agent-vm/src/controller/controller-runtime.ts:506-543](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/controller-runtime.ts#L506); [packages/agent-vm/src/controller/workspace-git/workspace-git-operations.ts:458-500,579-775](https://github.com/ShravanSunder/agent-vm/blob/38569fca72e88a74162b75f5401949ef19cd5a29/packages/agent-vm/src/controller/workspace-git/workspace-git-operations.ts#L458).

## 4. End-to-end paths

These are **source-predicted journeys**, not executed tests. They expose where a return or refusal can occur.

### Start an agent-capable Gateway

1. CLI loads config and checks a prepared image; missing/stale selection stops startup. It selects the provider composition and starts the controller.
2. Controller takes the ownership lock and reconciles old recorded VM trees. Unsafe cleanup blocks successor admission. It assembles policy/approval/OAuth/lease services and opens loopback HTTP.
3. Controller selects Hermes lifecycle, creates exact Gateway/cohort/role identities, materializes protected profile state and finalizes separate Node/Python boot inputs in memory mounts.
4. Provider starts the VM. Image init launches Node and Python siblings. Private ingress is opened for control; this is distinct from publishing ordinary framework ingress.
5. Python validates the configured profile cohort, connects/handshakes over private UDS, prepares tool catalogs, installs hooks and calls upstream `hermes_gateway.run_gateway()`.
6. Host performs signed readiness then Socket.IO hello, registers domain handlers and aggregates VM liveness, control, Node attachment/readiness and framework-native health. The admission state machine publishes the ordinary ingress routes. Startup returns only after admitted; control/runtime material is recorded.
7. **Unknown external-image edge:** actual channel message → Hermes session/model loop → installed hooks. Local code admits an explicit `SessionSource.profile` and supplies the hooks, but that upstream call chain was not opened. Do not draw it as verified execution.
8. A hooked terminal operation uses Python SDK sandbox methods over UDS; Node acquires current Tool VM binding/active-use and uses strict SSH; output, exit/outcome and cancellation return to Python. Failure/teardown releases the relevant owned use/group; VM teardown is separately host-owned.
