# OAuth broker domain and split-database constraints

Researcher: 🛠️ Worker R3. Source snapshot: `design/portable-tool-portal-hosts`, `8535fdd433dc90fed627ee7a05f63e59d58cf8ee`, inspected 2026-10-15. Read-only source research; no database, account, credential, deployment, or running service was inspected or changed. No tests were run. This is evidence about checked-in behavior, not a claim about the current Mac deployment.

**FACT, high confidence:** “Policy/grants in cloud, credentials on Mac” crosses an existing storage boundary: grant authority and credential custody currently occupy the **same authorization row**. Account policy is a separate encrypted companion row; human admission and profile defaults originate in authored configuration. Exact-call approval is a different controller ledger and presenter path. Evidence: [authorization schema:30–94](/Users/shravansunder/code/projects/agent-vm.design-portable-tool-portal-hosts/packages/oauth-broker/src/catalog-schema.ts:30), [config contracts:112–176](/Users/shravansunder/code/projects/agent-vm.design-portable-tool-portal-hosts/packages/config-contracts/src/oauth-config.ts:112), [policy compilation:474–520](/Users/shravansunder/code/projects/agent-vm.design-portable-tool-portal-hosts/packages/config-contracts/src/oauth-tool-portal-config.ts:474), [approval boundary:696–721](/Users/shravansunder/code/projects/agent-vm.design-portable-tool-portal-hosts/docs/reference/configuration/system-json.md:696).

```text

  owner/editor agent admission           account identity + grant + tokens
  complete agent profile                 |
  defaults + ceiling + command support    v
             |                      One controller SQLite connection
```

**INFERENCE, high confidence:** Moving only rows without changing their consumers cannot preserve this model. The split needs an explicit new authority/consistency contract; this report identifies the obligations, without selecting that design. Supporting transactions and final checks are itemized in Q4–Q5.
