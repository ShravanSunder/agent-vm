1. How organizations' Fleet data are kept apart (OD8)

You decided one Fleet central serves several organizations with nothing shared between them (U27). Fleet central keeps each organization's admissions and roles in its own object. Workspaces, projects and boards, though, live in one Fleet object today, shared by everyone, and no earlier decision says how to split them. This is a storage boundary, so it is yours. Both reviewers agree the choice is real and the costs below are honest. The Advisor added that option A is still a storage cutover, not "no migration".

If you defer: the organization authority, machine login and the sign-in work go ahead. The Fleet object's addressing, organization-scoped project lookups, the filtered view, session registration and your production switch wait.

2. Which VMs the Router must be proven in (OD10)

You said Routers must run on "linux or fmvs" and that "a firecracker vm could communicate to a router outside vm". The reviewers found that agent-vm's own VMs boot through Gondolin on QEMU, not Firecracker, and nothing in the product runs Firecracker today. The Router doesn't care which hypervisor runs it. What matters is a Linux guest with no Keychain, logged in by the thing that created it. Both reviewers say a QEMU run must not be reported as Firecracker proof, so this needs your word.

3. Linux machines without systemd (OD9)

A machine you log in by device code keeps one refresh credential in an encrypted store. On macOS that store's key lives in the Keychain. On Linux, the design takes it from a systemd encrypted credential, sealed with the machine's TPM when it has one and read by the Router running as a service. A Linux machine that doesn't run systemd has no such key. Your "Linux and Firecracker, everything a Router needs" (U35) doesn't say whether that case must log in by device code.

4. A Linux CI job in codex-router

Proving the whole machine login on Linux needs a Linux machine running the Router as a systemd service. The only Linux machines available are GitHub Actions runners; sunclaw is a Mac. codex-router's existing Linux jobs can already run the secret store's own tests. The whole journey needs one new job, and check gates are yours to change.
