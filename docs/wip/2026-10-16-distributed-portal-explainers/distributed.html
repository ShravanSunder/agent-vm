Distribution changes who owns the truth

We already have remote MCP connections and a managed approval RPC. The remaining work is the contract for policy freshness, exact approvals, one-use dispatch and recovery across independently failing processes. A database adapter alone does not supply that contract. **Replicas** jointly serve one authorization domain. **Independent portals** each own a domain and delegate requests between them. These are different systems even when both reuse identical packages.

Replicas and independent portals

Verifies the request and routes admission to the authority owner. Owns current policy, operation identity, approval decisions and atomic consumption. Can recover the same caller's work through that authority, under current access checks.

One-use decisions must be ordered at the same owner. A replacement front end must not generate another dispatch permit for work that may already have been sent.

Cloud caller policy, approval and operation record. Resource audience, verified acting identity, exact work and correlated operation references. Contract still to settle. Independent local admission, resource limits, approval requirements and outcome owner.

A cloud transaction cannot atomically commit a Mac or provider effect. Inner pending must remain pending at the outer portal; a lost reply must remain uncertain until evidence resolves it.

What identity survives the Cloudflare entry?

Cloudflare forwards a client-name diagnostic in `X-Forwarded-User-Agent`. Its documentation explicitly says this client-controlled value must not be used for authentication or authorization. Calling a client “Codex” or “Claude Code” cannot choose its permissions.

The cloud-to-computer contract

The owner selected a cloud gateway above computer MCP servers. The responsibilities below make that topology concrete. They do not select a token format, database, approval owner or a new public API. Ordinary third-party MCP providers keep their own protocols; our controlled computer servers need this additional contract.

Preserve the inner portal's meaning

The agent's request and authenticated ownership. Records which computer operation carries out the requested action. Admission, any required approval and execution observation. Returns a typed result or an unresolved operation handle. Pending stays pending. Confirmed completion stays completion. Unknown stays unknown until evidence resolves it. Current [provider normalization](../../../packages/mcp-portal/src/mcp-provider-backend/mcp-provider-capability-backend.ts) marks a successful core item as completed and keeps its structured payload as the value. That is valid for an ordinary completed provider call, but it does not interpret a nested portal's pending operation as the pending outcome of the requested leaf action. A portal-aware adapter needs to preserve inner approval, operation and uncertainty semantics. Source finding, not a live two-portal test.

Discovery needs the same explicit composition: importing a computer portal's four wrapper tools is different from federating the permitted leaf-tool catalog. The gateway must know whether a configured provider is an ordinary MCP server or one of our composable computer portals. Exact presentation and protocol negotiation remain design work.

What the current code demonstrated

Two distinct Node processes imported the actual unchanged standalone approval module. Each received the same test-only intent, signing material and proof. Each authorized its first submission; each rejected local reuse as already armed/ambiguous. The experiment sent no tool request and caused no provider effect. It demonstrates local consumption ownership, not an HTTP deployment exploit.

State needs different owners and lifetimes

Tool calls and management take different paths

Gateway verifies caller → portal resolves binding → authority checks current policy and required approval → connector sends admitted work → observation is recorded. Before dispatch: deny, pending, conflict or unavailable can prevent a send. After possible dispatch: no automatic replay without the resource contract's evidence. Separately authorized human or agent management client → validate exact decision/change and expected revision → authoritative state transition → acknowledged active/applying/conflict result. Tool credentials alone do not grant configuration or approval powers. A saved cloud request is not proof that Mac-owned policy has activated.
