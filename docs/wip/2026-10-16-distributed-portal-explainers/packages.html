Keep together or extract authorization?

Separate exported modules for portal orchestration, authority contracts/rules and Node/Worker host composition. Other consumers import only the authority module. Keep the HTTP MCP connector usable without importing stdio or CLI effects. Hosts combine it with Tool Portal through narrow interfaces.
Discovery, binding selection and invocation orchestration. Protocol-neutral authorization, exact approval and operation-admission contracts. Local and remote adapters share the same meaning. Uses the narrow authority contract and performs its own enforcement without a full Tool Portal.
Keep current packages and single-owner contracts for existing deployments. This avoids migration work, but does not satisfy the requested portable Worker and distributed public-authority behavior. It is useful as the comparison baseline, not a claim that the new requirements are already met.

Recommendation and its limit

Make the authority boundary independently consumable and host-neutral. Keep tool orchestration and MCP transport outside it. Then choose an exported module or a package from real consumer/dependency requirements. No need to create a separate service merely because there is a separate package.
