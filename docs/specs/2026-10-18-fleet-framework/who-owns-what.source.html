Fleet Framework: who owns what

- **agent-collaboration** owns who is in the fleet and how they talk: the registry, channels, mailboxes, the inbox classifier and the workspace chief. - **agent-vm's Tool Portal and MCP Portal** own what members can *do* with tools: the tool buckets, each workspace's and each agent's subset, registration config, and which calls need approval. They use agent-vm's controller for credentials and approval decisions. - **The AgentStudio daemon** owns a person's *console into a VM*: one Host per isolation unit, Gateways, sessions, terminals, worktrees, and the apps you use. Coding agents run in its terminals; persistent bots run on their own agent servers. No product owns VM provisioning yet (Q-B6). - **People** set the rules: you add managers; managers (per workspace) configure their agents' tools; both workspace owners agree before a channel crosses between workspaces. Every security and permission change is logged. **The product split itself is a proposal (🟡), not your decision.** The Advisors drew it from your answers. Your decisions say *what* must happen (F-rows); they rarely say *which product* does it. Marks: - ✅ you decided it (F-n or D-n points to your words in the [parent doc](2026-10-18-fleet-framework.md)); - 🟡 proposed by the Advisors; - ❓ open, with its number in [open-questions.md](open-questions.md). The fastest check is [Unsettled ownership](#unsettled): nine things that still have two candidate owners, or none.

Inside the Tool Portal and MCP Portal

The 🦁 agent-vm Lead's Program Design (`docs/specs/2026-10-14-portable-tool-portal-hosts/program-design.md`, package table) separates three kinds of code. Only the left column exists as code; the middle one is a proposal. - **Tool Portal**: resolves capabilities, plans authorized calls, calls backends (Tool VM runner, MCP, controller actions) - **MCP Portal**: proposed to become an **MCP Gateway** (what agents connect to) plus **MCP connectors** (outbound MCP sessions) 🟡 - No listener, credential database or VM provisioning of its own 🟡 - **tool-access**: shared contracts; **authorization** (workspace and agent subsets, the named-workspace check) and **approval rules** as separate entry points 🟡 - **credential-broker**: choosing and holding credentials, account policy (team vs personal, F-35) 🟡 - Usable without either portal runtime. No identity enrollment storage, no listeners, no durable approval records 🟡 - **OAuth broker** and **secret management** (1Password, environment) - **Managed persistence and approval authority**: the controller decides managed approvals (`mcp-portal.md:35`) - The shared modules reach these through ports; extraction doesn't change who owns them 🟡 Identity comes in through verifier and registry contracts (agent-collaboration's job); there is no portal-owned identity database 🟡. - **The harness and its memory**: we register an agent *in* a harness, not the harness ✅ F-23. Memory is out of scope; assume memory per bot, and files are memory ✅ F-18 - **Client, agent loop and execution are separate layers**. Sharing an execution environment shares data, never the agent loop ✅ F-6 - **A registered bot's VM**: it runs in its own VM, which we don't control ✅ F-11 - **Cloud agents** are a different tool, not a local session ✅ F-7 - **Model providers** see context; that's fine ✅ F-20. **Vendors** are talked to or used as tools ✅ F-19

Membership

**Membership is the record that someone belongs to a workspace.** It's the fleet registry's job (agent-collaboration 🟡). A member is a person, an agent or a bot ✅ F-4. Membership is what turns everything else on: | Membership gives | Decision | |---|---| | a mailbox, and sending and receiving where a channel allows | ✅ F-21 | | that workspace's tools, through its subset and the agent's own subset | ✅ F-24 | | a workspace it can name on a tool call | ✅ F-32 | | a view of its bots' terminals, for people who are members | ✅ F-33 | A bot gets membership by being registered into the workspace ✅ F-10. A coding agent started on a machine is a member of that machine's workspace ✅ F-38, F-39 (what it acts for: ❓ Q-C14). Removing it drops its undelivered messages ✅ F-26. A bot can be a member of several workspaces, and none of them is its home ✅ F-5.
