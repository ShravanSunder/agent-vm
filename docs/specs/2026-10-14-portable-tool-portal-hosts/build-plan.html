How sign-in fits

People and machines get different front doors (F-64, F-65). The sign-in service runs Better Auth on a Cloudflare Worker with D1. People sign in once and receive a short-lived token for each service they use; each service checks that the token was made for it. Machines keep using Cloudflare. What the sign-in design must get right, from the Advisor's checks: - **Revocation is not instant by default.** A cached session can outlive a revoked account, so Tool Portal checks the person's current manager status at every Accept, not only the token. - **A passkey login is not an Accept.** It proves who signed in, not that they pressed this Accept; that check stays with the console's design (F-57). - **One membership registry.** Better Auth's organization feature isn't used for workspaces; the fleet owns membership. **Open in that design:** where it lives (my default is `agent-fleet-tools`, as `@agent-collaboration/auth`), private mode first (approved accounts only), then public mode.
